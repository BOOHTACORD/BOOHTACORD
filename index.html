ДЛЯ АДМИНИСТРАТОРА

Развёртывание
своего сервера.

Сервер включает API, веб-клиент, PostgreSQL, Caddy и медиасервер LiveKit. Ниже — подготовка, тестовый запуск из исходников и порядок установки рабочего выпуска.

Что понадобится

  • Linux-сервер с Docker Engine и плагином Docker Compose. Для запуска из исходников — Git; для рабочего выпуска — также Python 3, OpenSSL и Bash.
  • Домен с DNS-записью на сервер и его доступный извне IP-адрес. Caddy обслуживает сайт по HTTPS.
  • Открытые входящие порты: 80/tcp, 443/tcp, 7882/tcp и 50000–50100/udp. Последние два нужны для медиа LiveKit.
  • PostgreSQL, API и управляющий порт LiveKit остаются в приватной сети Compose. Не открывайте их в интернет.

Для рабочего сервера

Рабочее окружение использует подписанный server bundle с готовыми образами API и web одной ревизии. Сборка на сервере через dev overlay предназначена для тестового запуска.

  1. Подготовьте runtime .env и доверенный публичный ключ подписи на сервере. Настройте trusted builder и окружение production в своём GitHub-репозитории.
  2. Получите успешный Build server для полного SHA из master. Доставка через Deploy production проверяет bundle и устанавливает готовые образы.
  3. Для повторной установки используйте Install retained release с ID успешной сборки и тем же SHA. Порядок подготовки хоста, установки и обновлений — в инструкции по выпускам.
Тестовый запуск через Docker Compose +

Команды ниже выполняются в Bash на тестовом Linux-сервере. Используйте отдельное окружение и свой домен. Они собирают API и web из исходников; для рабочего окружения следуйте порядку установки подписанного выпуска выше.

  1. Скачайте проект и подготовьте настройки

    git clone --branch master https://github.com/Egkurilov/BOOHTACORD.git
cd BOOHTACORD
cp .env.example .env
chmod 600 .env

    Откройте .env в редакторе. Замените значения replace-before-running собственными случайными секретами для POSTGRES_PASSWORD, LIVEKIT_API_KEY и LIVEKIT_API_SECRET. Файл хранится только у владельца сервера.

    PUBLIC_HOST
    Домен сервера, например voice.example.com, без протокола.
    PUBLIC_ORIGIN и VITE_PUBLIC_ORIGIN
    Одинаковый HTTPS-адрес: https://voice.example.com. Вторую переменную добавьте в файл.
    LIVEKIT_PUBLIC_WS_URL
    wss://voice.example.com/rtc — публичный адрес LiveKit через Caddy.
    LIVEKIT_NODE_IP
    Доступный извне IP-адрес медиасервера. Для удалённых клиентов значение 127.0.0.1 не подходит.
    API_IMAGE и WEB_IMAGE
    Для этого тестового запуска оставьте voice-platform-api:dev и voice-platform-web:dev из шаблона.

    Оставьте LIVEKIT_PRIVATE_HTTP_URL=http://livekit:7880. Если приватная подсеть конфликтует с сетью хоста, меняйте PRIVATE_NETWORK_SUBNET, PRIVATE_PROXY_IP и TRUSTED_PROXY_CIDRS согласованно — подробности конфигурации.

  2. Проверьте конфигурацию и запустите сервисы

    docker compose --env-file .env -f deploy/compose.yaml --profile operator config --quiet
docker compose --env-file .env -f deploy/compose.yaml -f deploy/compose.dev.yaml up --build -d
docker compose --env-file .env -f deploy/compose.yaml ps

    Compose запускает PostgreSQL, выполняет миграции и поднимает остальные сервисы. Дождитесь успешного завершения migrate и готовности сервисов, прежде чем создавать администратора.

  3. Создайте первого администратора

    Выполните bootstrap до открытия регистрации. Пароль вводится скрыто и передаётся через stdin, а не аргумент командной строки. В примере логин администратора — owner.

    read -r -s -p 'Пароль администратора: ' BOOTSTRAP_PASSWORD
printf '\n'
printf '%s\n' "$BOOTSTRAP_PASSWORD" | docker compose --env-file .env -f deploy/compose.yaml --profile operator run --rm -T bootstrap-admin --login owner --password-stdin
unset BOOTSTRAP_PASSWORD

    Повторный bootstrap не меняет существующего администратора или его пароль. Восстановление доступа выполняется отдельно — операционная инструкция.

  4. Проверьте доступность и подключите клиент

    curl --fail https://voice.example.com/api/v1/health

    Замените домен в команде своим. Откройте тот же HTTPS-адрес в браузере или укажите его в приложении и войдите как owner. Настройте каналы и разрешения, затем передайте адрес участникам.

    Health проверяет доступность API. Отдельно проверьте голос между двумя клиентами и демонстрацию экрана: успешный ответ API ещё не подтверждает работу медиа.

СПРАВКА

Частые
вопросы.

Остальное можно узнать в документации и репозитории проекта.

BOOHTACORD действительно бесплатный? +

Клиенты и опубликованные сборки доступны бесплатно. Подписка для голосовых каналов не нужна. Собственный хостинг, домен и интернет-трафик оплачиваются вами, если их предоставляет платный провайдер.

Можно просто скачать приложение и начать общаться? +

Для общения понадобится сервер BOOHTACORD: свой или тот, адрес которого вам дал администратор. Приложение подключается к этому серверу. Инструкция по развёртыванию — на этой странице.

Демонстрация экрана работает со звуком? +

В проекте реализована передача экрана и работа со звуком на поддерживаемых платформах. Конкретные возможности зависят от ОС, устройства и текущей сборки. Мы не обещаем одинаковое качество и частоту кадров для всех устройств.

Почему Windows и macOS могут предупреждать об установке? +

Текущие Windows-сборки выпускаются без Authenticode-подписи, а macOS-сборки не нотарифицированы Apple. Скачивайте файлы только из официальных GitHub Releases и при необходимости проверяйте контрольные суммы.

А что с iPhone и iPad? +

iOS-клиент есть в исходном проекте, но публичного релиза для установки сейчас нет. Как только такой релиз появится, ссылку можно будет добавить на эту страницу.
