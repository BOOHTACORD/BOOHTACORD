# UI/UX 2026 state matrix

This matrix records the client-side state contract and deterministic fixtures for epic [#289](https://github.com/BOOHTACORD/BOOHTACORD/issues/289), especially [#296](https://github.com/BOOHTACORD/BOOHTACORD/issues/296) and [#299](https://github.com/BOOHTACORD/BOOHTACORD/issues/299). It describes presentation only; it does not change API, ACL, session, or media contracts.

`Covered` means a deterministic test exercises the named state. `Partial` means the surface has domain-specific states that are not part of this issue's new HTTP fixture set. A simulated response is not evidence of a physical-device or production-service run.

## Cross-cutting rules

- Empty, stale, forbidden, offline, unavailable and degraded are distinct. A failed request never becomes “no items”.
- Recoverable errors permit deliberate retry; denial stops blind retries; mutations are never replayed automatically.
- Pending and completed outcomes use contextual Web live regions or Flutter Semantics. User messages, tokens, DM identifiers and attachment contents are not added to telemetry for these states.
- Old data stays visible only when explicitly marked stale or retained during refresh. Newer request generations win; disposed Flutter role requests cannot update the screen.
- Browser axe checks and Flutter Semantics-tree assertions verify accessible status regions. Physical VoiceOver/TalkBack walkthroughs and real-SFU fault recovery are separate release evidence, recorded in [`UIUX_2026_RELEASE_GATE.md`](UIUX_2026_RELEASE_GATE.md) and the [epic evidence](../../evidence/qa/uiux-2026-epic-289-2026-10-09.md).

## Evidence boundary for #299

The response matrix is deterministic and simulated; it does not claim a production-server fault injection or physical assistive-technology walkthrough. HTTP codes that do not apply to read-only surfaces are recorded as such. Voice/SFU recovery remains a separate evidence gate.
