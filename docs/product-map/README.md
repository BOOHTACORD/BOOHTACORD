# Карта продукта: начальная проекция

Это начальный инструмент для работы над #688, а не завершённая карта.
Он читает `tools/qa/local_features/features.json`, проверяет существующие
правила parity и выводит текущие сценарии без копии реестра:

```sh
python -m tools.product_map validate-parity
python -m tools.product_map matrix
python -m tools.product_map compare --platform web --platform windows --scope voice
python -m tools.product_map generate
python -m tools.product_map generate --check
```

В release workflow Windows, macOS и Android после действующей проверки
настоящих native-артефактов команда `release-snapshot` готовит отдельный
`feature-snapshot.json` в `.out/native-release/<platform>/`. Он содержит
SHA исходников, SHA проверенного manifest и независимые состояния функций;
существующий подписанный пакет и перечень его файлов не изменяются. Sidecar
сохраняется среди workflow evidence. Публикация и runtime в нём остаются
UNKNOWN/NOT_VERIFIED: наличие snapshot само по себе не подтверждает выпуск.
Пути для Web и iOS, приёмка на реальных артефактах и чтение release/deploy
receipts картой пока не реализованы.

Команда `generate` создаёт автономный предварительный просмотрщик
`docs/product-map/generated/index.html`. Его можно открыть в браузере без
сервера; поиск и ссылки вида `#feature/voice.long_recovery` работают локально.
Проверка `--check` обнаруживает устаревший файл и запускается в CI. Она
проверяет только эту проекцию, а не полноту карты или достоверность релизов.

В выводе отдельно представлены состояние исходного кода, релиз и runtime.
`UNKNOWN` означает отсутствие подтверждённой информации, а не отсутствие
функции. Объявленный в старом реестре runtime `PASS` показывается отдельно и
не считается подтверждённым новой проекцией без проверки доказательств.
Windows и macOS не наследуют статусы из Android, iOS или общего Flutter.

Каталог `product-map/features/` содержит сопоставления всех 23 текущих
parity-сценариев и 40 компонентов. Файлы используют JSON-совместимый
синтаксис YAML 1.2. Пути
компонентов разрешаются из авторитетного parity-реестра; каталог не хранит
вторую копию этих путей. Общий Web-компонент workspace указан один раз,
а Android- и iOS-адаптеры push отдельно. Охват функций за пределами parity,
серверные компоненты и остальные платформенные адаптеры ещё не
инвентаризированы. Сопоставление parity не подтверждает полноту карты.

Ещё не готовы: полноценный каталог и компонентный граф, ревизии поведения,
проверка поставок и откатов, полный интерактивный интерфейс, impact и контроль
изменений PR, а также приёмка AC-01…AC-18. Данные нельзя использовать для решения о
выпуске. Исходный parity-реестр остаётся авторитетным для своего покрытия.
