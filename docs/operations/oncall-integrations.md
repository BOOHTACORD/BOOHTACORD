# On-call: карта интеграций и отказов

Область: один deployment / одна гильдия. Владелец прикладного решения — API;
медиа передаёт LiveKit, API не проксирует RTP/RTCP. Начните с пользовательского
действия и найдите его строку; успешный HTTP health не доказывает доступность БД,
медиа, attachments или телеметрии. Источник архитектуры — [границы данных](../architecture/data-boundaries.md).

## Как использовать readiness без утечки

1. Обычный пользователь проверяет только `GET /api/v1/health`: `{status: ok}`,
   процесс liveness. Здесь нет адресов, DSN, exporter credential, списка комнат
   или зависимости от probes. Не направляйте load balancer на admin API.
2. Авторизованный ADMINISTRATOR открывает существующий
   `GET /api/v1/admin/readiness` в same-origin UI/devtools со своей secure
   HTTP-only cookie; не копируйте cookie в shell, issue или screenshot.
   Ответ `no-store`: 200 ready или 503 degraded. Просроченная/заблокированная
   session отвергается текущим server-side middleware; MEMBER/MODERATOR denied.
3. Проверки DB→SFU→storage последовательные, каждая 400 ms. `checked_at` относится
   ко всему вызову, `sampled_at` — завершённому probe; `timeout`/`busy` = unknown,
   не 0. DB pending count и storage byte headroom — private administrator data;
   raw underlying errors, hostnames и credentials не возвращаются.
4. Probe Ping/statfs только диагностирует. Он не включает admission, не проводит
   миграции, не удаляет files и не запускает media. Readiness ready не доказывает
   capacity, проигрывание, writable storage или подтверждённое moderation.
   Если БД сломалась до проверки session, используйте инфраструктурного
   оператора и приватные signals: API admin role не даёт SSH/DB credentials.

## Права, восстановление и evidence

Application administrator видит readiness через свой ACL. Operator с отдельным
инфраструктурным доступом видит private metrics, Grafana/Tempo и deployment
config; app admin автоматически таких прав не получает. Dashboard links могут
вернуть access denied без соответствующей Grafana org/role — не обходить ACL.
Исходники нового Incidents/QoE dashboard доступны в репозитории, импорт и live
проверка нужны отдельно. Не выводить `.env`, `docker inspect` secrets, token,
RTCP/RTP/media, SQL values, message/DM body или ICE/SDP в общие evidence.

- Source/native verification: [issue #7 evidence](../../evidence/observability/issue-7-oncall-integrations-2026-10-07.json).
- Production outage matrix: NOT_RUN. Этот пакет не останавливает рабочие сервисы,
  не меняет production config и не выполняет rollout. Для каждого ряда на
  изолированном deployment: controlled failure → симптом/timeout → freshness/
  status → разрешённое восстановление → повтор той же проверки. Сохранять только
  synthetic/aggregate outcome, pinned digest, UTC time и безопасную correlation.
- POC-03: BLOCKED. [Имеющийся preflight](../../evidence/poc-03/poc-03-preflight-2026-09-25-001.json)
  содержит connected media / old API и SDK token replay NOT_RUN. Выполнить семь
  действий [revocation runbook](../runbooks/media-revocation.md) и оба replay
  класса на изолированных двух клиентах; HTTP revoke/outbox/RoomService ack
  не превращать в PASS без direct media evidence.
- POC-02 / QA capacity: этот пакет ничего не измеряет и ёмкость не заявляет.
  Нагрузочная/физическая приёмка следует [media profiles](../runbooks/media-profiles.md).

## Проверка актуальности карты

```text
python -m unittest tools.verify.oncall_map.test_check -v
python -m tools.verify.oncall_map.check
python -m tools.verify.links.check
```

Первый check автоматически входит в tools Python regression suite / CI contracts.
Изменение явных source deadlines, новых SQL/body/retry/TURN настроек блокирует
проверку до синхронизации карты. Проверка сверяет versioned anchors и ссылки;
это source regression, не runtime failure injection и не гарантия поведения
OS/SDK/Caddy defaults. При изменении соответствующей pinned зависимости заново
проверить её defaults и измерить isolated failure path, не молча менять anchor.
