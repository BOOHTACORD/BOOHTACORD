# ADR-003: in-memory limits аутентификации

Статус: принято для single-process MVP.

API применяет fixed-window limits: пять registrations за 15 минут, 32 login attempts за пять минут на source IP и 200 login attempts за пять минут на процесс API. Лимит источника пропускает 20 разных пользователей за NAT и оставляет 12 попыток на повтор; глобальный бюджет ограничивает суммарное число допущенных до проверки аккаунта попыток. Запрос, отклонённый лимитом источника, не расходует глобальный бюджет. Оба бюджета учитывают успешные и неуспешные попытки; 429 содержит `Retry-After` и не продлевает окно. На нормализованный логин дополнительно действует лимит восемь попыток за 30 секунд, а KDF ограничен процессным семафором. Это уменьшает, но не устраняет риск исчерпания общего бюджета распределённой атакой: при превышении легитимные входы тоже получат 429 до окончания окна. Ограничения процессные, не суммируются между экземплярами и сбрасываются при перезапуске; для горизонтального развёртывания нужна отдельная политика.

Source limiter хранит не более 10 000 активных окон; при заполнении новые источники отклоняются до освобождения места, существующие окна не вытесняются. Общий limiter использует один фиксированный ключ. Метрики содержат только фиксированные классы limiter, без адресов и логинов. Защита не предполагает неограниченного повторения 429 клиентом.

Контейнеры API приватны, а Caddy — единственный public ingress, поэтому limiter использует первый valid client address из `X-Forwarded-For`, который устанавливает Caddy; malformed values заменяются непосредственно подключённым address. Документированное поведение Caddy по умолчанию игнорирует входящие forwarded values и устанавливает собственные: <https://caddyserver.com/docs/caddyfile/directives/reverse_proxy>. Если topology получит upstream CDN/load balancer, настройте Caddy trusted proxies до опоры на этот header.

Limits — baseline защиты от abuse, а не distributed quota. Redis намеренно не добавляется. Для будущего horizontal deployment нужна измеренная замена и ADR. Upload имеет отдельный rate-limit leaf, поскольку ему требуется account- и byte-aware enforcement.
