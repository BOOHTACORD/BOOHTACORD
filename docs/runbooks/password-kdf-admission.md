# Допуск к Argon2

SEC-004 (#532) использует один общий допуск в модуле `identity/password` для
Hash, Verify и VerifyUnknown. Все функции требуют context. HTTP services
передают request context; bootstrap/recovery CLI передают контекст своего
сервиса. Единственный startup dummy создаётся с явным Background context до
обслуживания запросов. Compatibility wrapper без context отсутствует.

Политика: четыре активных вычисления на процесс, ноль ожидающих, максимальное
ожидание места — ноль. Пятый запрос сразу получает типизированный `ErrBusy`.
Контекст проверяется до допуска, после выдачи permit непосредственно перед
KDF и после фактического вычисления. Увиденная отмена исключает новое KDF и
возвращает context error вместо hash/вердикта. Уже начатая синхронная Argon2
сохраняет permit до реального завершения; отдельная goroutine для продолжения
работы после отмены не создаётся. Освобождение permit идемпотентно.

Предел четырёх сохранён из действующей реализации; параметры ADR-001 неизменны.
Локальные штатные Go benchmark-прогоны (Apple M4 Pro, Go 1.26.4) измерили 14–17 ms
и 19.93 MB allocations на Hash. Это основание выбрать простой отказ без
накопления чувствительных запросов, а не выбирать произвольную очередь:
вычисления короткие, следующий ручной запрос может занять освободившееся место.
Четыре Argon2 занимают до 76 MiB собственно рабочих областей по параметру m;
этот расчёт не равен RSS процесса или измеренной production capacity.

Это process-local защита. После restart счётчики обнуляются; несколько реплик
имеют собственные пределы, общей deployment-wide квоты этот механизм не даёт.
Новых Redis, глобальной map ключей и секретов в очереди нет. Сетевые IP-лимиты,
Origin/CSRF, лимит тела, session cookie и серверные ACL сохранены. Account
admission (#533) описан в `login-account-admission.md` и резервирует бюджет до
account lookup/verifier; reset preflight (#535) остаётся отдельной задачей.

Login, register, reset complete и смена пароля отвечают при `ErrBusy` одинаковым
503 `AUTH_BUSY`, `Cache-Control: no-store`, `Retry-After: 1`, без cookie и
мутаций. Это инфраструктурная занятость, а не 401/неверные credentials.
Web и общий Flutter показывают задержку ручного повтора, сохраняют editable
form/существующую cookie и не планируют автоматический retry. Обычные ошибки
503 (например, maintenance) сохраняют свои сообщения. Транспортная отмена
передаётся как context error; для уже ушедшего клиента HTTP-доставка ответа
не гарантируется. Неоднозначная доставка мутации не означает её rollback.

Private `/metrics` публикует только агрегаты без labels:
`voice_platform_auth_kdf_active`, `waiting` (всегда 0), `capacity`,
`rejected_total`, `cancelled_total`, `admission_seconds` и `work_seconds`.
Последние два имени обозначают histogram families. Время admission — время
немедленного решения, не пребывание в очереди; work включает завершившуюся
работу отменённого запроса и одноразовую startup-инициализацию. Счётчик cancelled
отражает наблюдённую отмену, а не все отключения сети. Метрики этого коллектора
не подразумевают автоматическую OTLP-доставку. Логины, пароли, hash/salt,
account/session/reset IDs в метрики и диагностику не передаются.
