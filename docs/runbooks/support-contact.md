# Поддержка своей установки

Кнопка «Помощь и обратная связь» открывает существующий личный диалог с одним назначенным **активным локальным аккаунтом**. Создайте аккаунт обычным приглашением и авторизацией; отдельного технического пароля или привилегий чтения DM нет. Один оператор отвечает из собственного обычного списка личных сообщений. Не используйте общий пароль для нескольких сотрудников.

## Назначение владельцем сервера

После обновления backend миграция создаёт пустую singleton-конфигурацию. Выполните локально в доверенной операторской среде с доступом к контейнеру API и его DATABASE_URL:

```sh
docker compose exec api /support-contact status
docker compose exec api /support-contact set --account-id '<UUID активного локального аккаунта>'
docker compose exec api /support-contact clear
```

В заменяющей Compose-конфигурации используйте имя своего API-сервиса. UUID берётся из локального администрирования/базы; команда не принимает display name. Не публикуйте UUID, DATABASE_URL или пароли в issue, `.env.example`, логи CI. Бинарник также запускается непосредственно на доверенном сервере с установленным DATABASE_URL. Это операционная команда владельца, не клиентский HTTP API. Ограничивайте доступ к Docker/БД действующей моделью эксплуатации.

`set` отклоняет несуществующий/заблокированный аккаунт. `clear` отключает точку входа. Изменение фиксируется metadata-событием `SUPPORT_CONTACT_CHANGED` (revision/enabled и локальный target account), без текста и файлов. После изменения обновите список DM или нажмите `?`. При отсутствии назначения, блокировке или входе самого оператора показывается спокойное объяснение; отправки «в никуда» нет.

## Смена оператора и приватность

Смена назначения меняет только контакт для дальнейшего входа. **Старые DM остаются с прежними двумя участниками**; новый оператор не получает историю или файлы прежнего оператора. Уже существующий парный DM с новым оператором переиспользуется. Интерфейс объясняет смену и показывает старый диалог под обычным именем прежнего участника. Миграция старой истории, очередь сотрудников и общая staff inbox не входят в MVP.

Все сообщения, replies, лимиты (8000 Unicode-символов, до 10 файлов по 25 000 000 байт), history/unread/read cursor, загрузка/preview/download и realtime используют существующий DM путь. Администратор не может читать чужой DM. Поддержка конкретной установки не означает связь с разработчиком центрального продукта; межсерверной пересылки нет. Opt-in телеметрия не разрешает отправлять обращения.

## Ручной triage в публичный GitHub

Обсуждайте обращение приватно в BOOHTACORD. Только если нужна техническая задача, самостоятельно напишите обезличенное описание в существующем `Egkurilov/BOOHTACORD`, при необходимости с меткой `support-feedback` и `bug`/`enhancement`. Проверьте черновик человеком перед публикацией:

- обобщённый симптом, версия и платформа без персонального следа;
- воспроизведение на **синтетических данных**, ожидаемое и фактическое поведение;
- проверяемые критерии исправления.

Не копируйте исходные DM, ответы, снимки/видео/файлы/логи пользователя, private hostname/IP, имена/email, user/install/session/flow/media IDs, токены, исключения или приватные ссылки. Не публикуйте даже ссылку на приватную беседу. Метка не делает публичную issue приватной. Ответьте пользователю в исходном BOOHTACORD DM; закрытие GitHub issue не является ответом пользователю.

Никаких GitHub API/webhook, автоматического экспорта/псевдообезличивания, private repo, App, `/reply` или outbox в этой реализации нет.
