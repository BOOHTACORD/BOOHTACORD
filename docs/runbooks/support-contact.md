# Контакт поддержки установки

По [ADR-029](../adr/ADR-029-product-support-github-bridge.md) поддержка продукта
включена по умолчанию. Кнопка `?` открывает парный чат со служебным собеседником
BOOHTACORD. После явного согласия новые текст и файлы публикуются в GitHub;
ответы оператора возвращаются в тот же чат. Публичность постоянно показана.
Эксплуатация шлюза: [product-support-gateway.md](product-support-gateway.md).

## Команды владельца установки

Запускайте в доверенной среде контейнера API с его существующим DATABASE_URL:

```sh
docker compose exec api /support-contact status
docker compose exec api /support-contact product
docker compose exec api /support-contact set --account-id '<UUID активного локального аккаунта>'
docker compose exec api /support-contact clear
```

`product` включает общую поддержку; `set` назначает обычный активный локальный
аккаунт; `clear` отключает точку входа. UUID берётся из локального администрирования,
display name не является идентификатором. Не публикуйте DATABASE_URL, account UUID,
seed или пароли в issue/CI. Команды не дают владельцу права чтения чужих DM.

Миграция сохраняет явно назначенного локального оператора и явно отключённую
поддержку. Старое пустое начальное назначение становится поддержкой продукта.
После `clear` включайте общую поддержку командой `product`. Смена контакта
меняет только дальнейший вход: прежние участники/история DM не меняются,
новый оператор не получает старые тексты/файлы. Публикации старой истории нет.

## Локальная поддержка

В режиме `set` сообщения остаются обычным DM с назначенным человеком. Оператор
входит под собственным аккаунтом и отвечает из своего списка личных сообщений.
Администратор не может читать чужую переписку. Не используйте один пароль на
нескольких сотрудников. Все ресурсы используют штатные серверные ACL.

Заблокированный/отсутствующий контакт недоступен; оператор видит объяснение и
отвечает через обычные DM. После смены контакта обновите список или нажмите `?`.
Opt-in телеметрия не разрешает экспорт переписки.

## Локальная проверка

```sh
python3 -m tools.qa.support_contact.run
python3 -m tools.qa.support_contact.native --platform android --device emulator-5554 --output .out/support-native-android-RUN
python3 -m tools.qa.support_contact.native --platform ios --device '<UUID BOOHTACORD QA Simulator>' --output .out/support-native-ios-RUN
```

Runner принимает выделенные QA-эмуляторы, создаёт временную БД и синтетические
аккаунты. Сначала проверяет публичное предупреждение, согласие и composer,
затем локальное назначение, текст/файл и ответ оператора. Ресурсы удаляются после
прогона. Публичные issue при каждом запуске не создаются. TLS-разрешение действует
только для точного сертификата временного `https://localhost:4810`. Native upload
проверяется существующим API; системный picker, физические устройства и качество
media этим не подтверждаются. Живой GitHub bridge проверяется отдельным
контролируемым синтетическим прогоном с release evidence.
