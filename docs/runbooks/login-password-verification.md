# Проверка пароля при входе

Пароли пользователей сохраняют формат и стоимость Argon2id из ADR-001. При
запуске процесса модуль password один раз создаёт фиктивный хеш через обычный
`Hash`: случайная соль 16 байт, ключ 32 байта, `m=19456,t=2,p=1`. Полученное
значение проверяется общим decoder. Ошибка генерации или формата останавливает
запуск до обслуживания запросов с фиксированным сообщением
`password dummy initialization failed`; причина, соль и хеш не выводятся.

Для отсутствующего аккаунта `VerifyUnknown` выполняет один обычный `Verify` с
этим хешем через тот же общий semaphore. Совпадение с фиктивным паролем не
авторизует пользователя: сервис всегда возвращает `ErrInvalidCredentials`.
Неизвестный логин, неверный пароль существующего аккаунта и неверный пароль
заблокированного аккаунта имеют прежний ответ 401 `UNAUTHENTICATED`, одинаковое
сообщение и не создают сессию/cookie. Правильный пароль заблокированного аккаунта
по-прежнему даёт 403 без сессии.

Ошибки фиктивного verifier не игнорируются. Если инвариант нарушен во время
работы, сервис возвращает внутреннюю ошибку, а HTTP — существующий безопасный
500 `INTERNAL`, без cookie. Внешний контракт, схема БД и клиентские формы не
меняются; сброс существующих паролей не требуется.

Сетевые лимиты и предел четырёх одновременных Argon2 на процесс сохраняются.
Отказ внешнего IP admission не выполняет KDF ни для известного, ни для
неизвестного логина. Допущенная неизвестная ветка теперь выполняет настоящую
работу, поэтому её стоимость выше дефектной прежней ветки. Исправление порядка
account admission (#533) и ограничение/отмена очереди KDF (#532) остаются
отдельными задачами; этот фикс не доказывает защиту всего deployment от
перегрузки. Новых метрик и логов с идентификаторами нет.

Регрессии используют штатный Go `golang.org/x/crypto/argon2`, счётчик реальных
KDF через тестовый seam и синтетические in-memory хранилища аккаунтов/сессий.
Одноразовое создание хеша при запуске не входит в счётчик запросов. Равенство
числа KDF не является доказательством невозможности сетевого timing analysis.
