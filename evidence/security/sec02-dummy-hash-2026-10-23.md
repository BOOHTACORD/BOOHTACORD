contract. Implementation under test:

## Regression: RED → GREEN

Before implementation, `TestSecurity20261022DummyHashMustBeValid` failed on the
unchanged baseline because its dummy hash could not be decoded.

An additional baseline replay used Go `-overlay` with baseline password/service
sources and the new tests. The only baseline production-code instrumentation was
an alias of `argon2.IDKey` to the private counted seam: the real implementation,
parameters, defective salt and admission remained unchanged. Tests requiring
the new startup constructor/error-return API were excluded from this replay.

handler, IP limiter and Go Argon2id with synthetic in-memory account/session
stores. They do not query production accounts.

## Boundaries

UI runtimes and production deployment. No client source, UI state, API response
shape, schema, session policy or password parameters changed. This backend
restores the intended work inside the existing negative response; screenshot
and native acceptance claims are not made. Contracts verification is not
required by this change because no contract changes.

The existing four active Argon2 slots and external IP limiter remain. Account
admission ordering (#533) and bounded/cancellable KDF queue (#532) remain open;
no deployment-wide overload guarantee follows from this fix. Counts prove
execution of KDF, not network timing indistinguishability or production capacity.
