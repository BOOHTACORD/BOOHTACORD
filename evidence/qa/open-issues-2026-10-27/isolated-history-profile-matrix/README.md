## Dataset and execution recipe

Each size50/500/5,000/10,000 has normal0/50/100% reply references and separate
50/100% unavailable-target variants:20 datasets. All have fixed UTC timestamps,
deterministic variable multiline body lengths, one controlled author and unique
private row/client IDs. Seed CSV hashes bind the exact inputs to both source
variants. All20 were reconstructed from the actual server after profiling and
matched their original seed hashes before removal.

Unavailable targets use intentionally SQL-injected, FK-valid legacy cross-scope
references to one owned sentinel. Normal creation-path admission is NOT_RUN.
The actual scoped context API returns200/empty and the source controller maps
the absent requested anchor to unavailable; sentinel content is not returned.
The initial controller's404 expectation was wrong. Its setup exit1 and source
are retained; guarded resume validated existing data rather than reseeding it.

Actual store/API prefill happens while the component is unmounted. Historical
source retains N rows; current retains the latest min(N,500). The same available
dataset and newest target are mounted. Complete older/newer traversals for
all20 datasets/both sources were also observed in the retained diagnostic run.
Primary current profiles additionally click actual older/newer UI controls.
Prefill time is recorded separately from warm source-view mount timing.

## Measurement validity and counterexamples

Mount and controlled scroll callbacks execute in ordinary browser tasks.
Every profile first schedules an intentional120ms task and requires a live
LongTask observation. This calibration lies outside all measurement windows.
Mount records synchronous work and time to two animation-frame callbacks;
five controlled scrolls record callback-to-two-frame time. These are not INP,
trusted-input latency, physical display presentation or a production SLO.
LongTask entries and overlap windows are retained; numerical zero is accepted
only with successful per-profile instrumentation selftests.

Heap values include raw and explicitly collected-GC observations at empty,
prepared, mounted and reset stages. GC runs outside mount/scroll windows.
The compared delta is retained JS heap over that profile's empty controller;
it is not total browser/OS memory, peak RSS, or proof about memory leaks.
DOM counts, cache/cursor bounds, focus and geometric observations are actual.

The initial direct-inspector run retained71 completed profiles, including all
20 source pairs once. Ten mounts over100ms lacked a corresponding LongTask.
Only its owned controller tree was deliberately stopped, terminal exit1 and
closed ports verified. Its raw RUNNING checkpoint is historical, not a live
process. Those LongTask zeros are excluded from acceptance; exact inputs and
interruption receipt remain in diagnostic-inspector/. Primary120 profiles
complete after repair. Initial smoke receipts are retained separately too.

The provisional comparator of the first visible row was insufficient: an older
row can become visible above the original anchor. Raw flags remain retained.
Primary checks locate that same original message after paging and require its
offset within2px; all30 applicable checks pass. This was a controller-oracle
correction, not a confirmed product failure. The same64-row DOM guard rejects
45 actual historical-source cases of500+ rows; current cached/visible windows
remain bounded. The known uncommitted-edit counterexample remains separate.

## Limits and cleanup

This is the actual history component/store with real owned API data and fixed
toolchain, not an original shipped historical binary, cold deployed app,
native/physical or API Origin-policy acceptance. The source variants also
contain unrelated UI changes; no pure141 causal speedup is claimed. One source
context runs at a time; host CPU affinity/thermal/other-work isolation is not
claimed. Some controlled scroll timings increase even as mount/heap decrease.
There are393 observed ResizeObserver-loop events across60 current profiles
(2–10/profile). Their source/production impact needs triage in141; no warning-free
UI acceptance is claimed. Existing uncommitted-edit loss remains its confirmed bug.
Private seed CSVs, identities, API payloads and raw logs are not exported;
runner recipes contain known synthetic literals. No screenshot/golden or
physical UI/media acceptance is claimed.

Cleanup briefly added an owned FK-support index after all measurements, then
dropped it; original index definitions match exactly. API topology confirms
own scopes absent before logout; the retained cookie is subsequently rejected.
One revoked session audit row remains. Original9 IDs/images/config/starts are
unchanged, ports private, restart0. Production/phone/router were untouched.
Remaining edit/delete/image/search/unread/account/logout clauses and required
platform/security/media/hosted gates stay separate;43 consolidation decisions
are untouched. Replay requires a fresh privately prepared packet; receipt
guards preserve existing inputs/results.
