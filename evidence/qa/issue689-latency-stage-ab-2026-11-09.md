## Diagnostic session-monitor interval comparison

- A separate, temporary diagnostic variant changed only the local periodic session-monitor cap from 1.5 s to 2.5 s; authorization and per-roster checks remained present. It was tested on synthetic fixture accounts only and is not a proposed production change. The original monitor source was restored after the experiment. This comparison did not prove the complete revoke-to-close bound for the variant, especially with blocked writers or failures.
- Four alternating 100-account, 20-empty-room cells each recorded 1,000 socket deliveries and zero duplicates within the bounded observation window, with stable source fingerprints and owned cleanup. The 1.5 s cells measured first-event p95 40.39 and 38.72 ms, with 85 and 68 revalidations during their respective first-event probe windows; the 2.5 s cells measured 67.66 and 47.36 ms with 58 and 50 revalidations. Maximum sampled quota-relative API CPU ranged from 34.58% to 37.74% across the four cells. Each variant's two API binary hashes matched each other. Summary and report paths: `Q:/Codex/issue689-latency/.out/latency-monitor-ab-20261109T165058Z/summary.json`.
- Fewer observed checks did not coincide with lower latency in these samples. This small, variable diagnostic experiment does not establish causation or justify changing the security interval; the earlier baseline/candidate latency difference and the unreproduced failed cell remain unresolved. Full capacity, slow-client, real media and immutable-release gates remain `NOT_RUN`.
