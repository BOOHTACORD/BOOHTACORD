# Issue 689: Android guest/auth maintenance handoff

- PASS: dedicated Android API 35 AVD against an owned local TLS/Go/PostgreSQL/LiveKit stack. The application obtained a public maintenance snapshot before login, completed closure of every tracked public socket before authenticated realtime became ready, obtained an authenticated maintenance snapshot, reconnected the roster, logged out and obtained another public snapshot. The tracked API saw zero legacy maintenance/roster streams or roster polling.
- Two earlier runs failed an assertion based on Dart WebSocket `readyState` after stream cancellation. Source inspection showed this property may remain `open` after the close operation; the final run instead verifies completion of `close()`. An independent regression test also requires handoff to wait for a late-opening socket to close and to fail closed if an opening cannot be canceled. The earlier failing runs were retained in `.out/local-features/issue689-roster-maintenance-android*` and are not counted as passing.
