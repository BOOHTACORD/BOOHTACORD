# Issue 689: event identity and revocation

- Issue #689 requires durable-event deduplication by `(kind, event_id)`. Focused tests demonstrated that the previous ID-only checks could suppress a different kind with the same ID in Flutter, Web's base delivery, Web's coalescer, and the server replay/live boundary. In particular, the Flutter test showed a normal message could suppress a later voice revocation with the same ID.
- Flutter now tracks the pair while retaining the original ID as the replay cursor. Web uses the pair both in serial delivery and when combining pending hints, while preserving ID-only cursor values. The Go replay boundary compares the pair. This does not change PostgreSQL's unique event-ID constraint or assert that an actual database normally emits collisions.
